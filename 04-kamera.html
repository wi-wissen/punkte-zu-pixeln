Kamera und Pixel

Die Welt besteht aus Dreiecken im Raum, der Bildschirm aus einem Raster von Pixeln. Der Weg dazwischen hat vier Schritte.

  1. Alle Punkte aus Sicht der Kamera angeben
  2. Punkte auf die Bildebene projizieren
  3. Für jedes Dreieck die bedeckten Pixel bestimmen und einfärben (Rasterisierung)
  4. Pro Pixel entscheiden, welches Dreieck vorn liegt (Tiefenpuffer)

Schritt 1: Die Sicht der Kamera

Die Kamera steht irgendwo in der Welt und blickt in eine Richtung. Damit sich leichter rechnen lässt, verschiebt und dreht man die ganze Welt so, dass die Kamera im Ursprung steht und entlang der z-Achse blickt. Das sind genau die Operationen aus Kapitel 1: erst die Kameraposition abziehen, dann um den Blickwinkel zurückdrehen. Danach ist z einfach die Entfernung in Blickrichtung.

Schritt 2: Projektion

Vor der Kamera steht im Abstand f die Bildebene. Der Bildpunkt eines Punktes P liegt dort, wo die Gerade von der Kamera zu P die Bildebene schneidet. In der Seitenansicht entstehen zwei ähnliche Dreiecke, und der Strahlensatz liefert:

y′ ÷ f = y ÷ z   ⟹   y′ = y · f ÷ z

Ziehe den Punkt PSeitenansicht: z nach rechts, y nach oben

Für x gilt dasselbe. Durch die Division durch z erscheint Entferntes kleiner: Das ist die ganze Perspektive.

def projiziere(p, f):
    x, y, z = p
    return [x * f / z, y * f / z]
Ziehen zum Drehen

Der Aufwand ist eine Multiplikation und eine Division pro Koordinate, für n Eckpunkte also O(n).

Schritt 3: Rasterisierung

Nach der Projektion sind die drei Ecken eines Dreiecks Punkte auf dem Bildschirm. Welche Pixel liegen darin? Das Werkzeug dafür ist die Kantenfunktion. Sie sagt, auf welcher Seite der Geraden von a nach b ein Punkt p liegt:

def kante(a, b, p):
    return (b[0] - a[0]) * (p[1] - a[1]) - (b[1] - a[1]) * (p[0] - a[0])

Das Ergebnis ist positiv auf der einen Seite, negativ auf der anderen und null genau auf der Geraden. Ein Punkt liegt im Dreieck, wenn er bei allen drei Kanten auf derselben Seite liegt. Geprüft werden nur die Pixel im kleinsten Rechteck, das das Dreieck umschließt:

flaeche = kante(a, b, c)
for py in range(y_min, y_max + 1):
    for px in range(x_min, x_max + 1):
        p = [px + 0.5, py + 0.5]                 # Pixelmitte
        g_a = kante(b, c, p) / flaeche
        g_b = kante(c, a, p) / flaeche
        g_c = kante(a, b, p) / flaeche
        if g_a >= 0 and g_b >= 0 and g_c >= 0:   # p liegt im Dreieck
            setze_pixel(px, py, farbe(g_a, g_b, g_c))

Gewichte: von den Ecken zu jedem Pixel

Die drei Werte g_a, g_b und g_c sind mehr als ein Test. Sie sind Gewichte, die zusammen immer 1 ergeben. An der Ecke a ist g_a = 1, auf der gegenüberliegenden Kante ist g_a = 0. Mit ihnen lässt sich jede Größe, die an den Ecken bekannt ist, auf jedes Pixel im Inneren übertragen:

wert(p) = g_a · wert_a + g_b · wert_b + g_c · wert_c

Textur

Genau so kommt das Bild auf das Dreieck. Jede Ecke kennt ihre Stelle (u | v) in der Textur, mit Werten zwischen 0 und 1 (Kapitel 2). Für jedes Pixel werden u und v mit den Gewichten gemischt, und an dieser Stelle wird die Farbe aus dem Bild gelesen:

def farbe(g_a, g_b, g_c):
    u = g_a * uv_a[0] + g_b * uv_b[0] + g_c * uv_c[0]
    v = g_a * uv_a[1] + g_b * uv_b[1] + g_c * uv_c[1]
    return textur[int(v * (hoehe - 1))][int(u * (breite - 1))]
Ziehe die Ecken a, b, c

In der Ansicht „Gewichte“ hat jede Ecke eine eigene Helligkeit, die Pixel dazwischen mischen sie. In der Ansicht „Textur“ ist die Textur ein Schachbrettmuster. Die gestrichelte Linie zeigt das umschließende Rechteck.

Echte Grafikkarten teilen bei der Texturberechnung zusätzlich durch die Tiefe, damit das Bild auf schräg stehenden Flächen nicht verzerrt wirkt. Das Prinzip bleibt dasselbe.

Schritt 4: Der Tiefenpuffer

Mehrere Dreiecke können dasselbe Pixel bedecken. Sichtbar sein darf nur das vorderste. Die Dreiecke vorher nach Entfernung zu sortieren, wäre aufwendig und scheitert, wenn sich zwei Dreiecke durchdringen. Die Lösung ist ein zweites Feld, so groß wie das Bild, das für jedes Pixel die Tiefe des bisher nächsten Dreiecks speichert. Die Tiefe z eines Pixels ergibt sich wieder aus den Gewichten.

tiefe = [[UNENDLICH] * breite for _ in range(hoehe)]

# ... in der Pixelschleife:
z = g_a * z_a + g_b * z_b + g_c * z_c
if z < tiefe[py][px]:            # näher als alles bisher?
    tiefe[py][px] = z
    setze_pixel(px, py, farbe(g_a, g_b, g_c))
Zwei Dreiecke, die sich durchdringen

Aufwand

Die Projektion kostet O(n) für n Eckpunkte. Die Rasterisierung kostet pro Dreieck so viele Schritte, wie Pixel im umschließenden Rechteck liegen. Der Tiefenpuffer braucht einen Vergleich pro Pixel und macht die Reihenfolge der Dreiecke gleichgültig. Entscheidend ist: Jedes Dreieck und jedes Pixel wird unabhängig von allen anderen berechnet. Deshalb kann die Grafikkarte Tausende davon gleichzeitig bearbeiten.

Merke: Projektion: x′ = x · f ÷ z und y′ = y · f ÷ z (Strahlensatz). Rasterisierung: Die Kantenfunktion entscheidet, welche Pixel im Dreieck liegen, und liefert Gewichte, mit denen Tiefe und Texturkoordinaten von den Ecken auf die Pixel übertragen werden. Der Tiefenpuffer speichert pro Pixel die kleinste Tiefe.
  • (1 | 0,5)
  • (4 | 2)
  • (0,5 | 0,25)
  • in der Mitte des Dreiecks
  • in der Mitte der Kante von a nach b
  • auf der Ecke c
Aufgabe: Berechne kante(a, b, p) für a = [0, 0], b = [4, 0] und die Punkte p = [1, 2] und p = [1, −2]. Was bedeutet das Vorzeichen?
Lösung anzeigen
Für [1, 2]: 4 · 2 − 0 · 1 = 8. Für [1, −2]: 4 · (−2) − 0 = −8. Die Punkte liegen auf verschiedenen Seiten der Geraden durch a und b.
Aufgabe: Ein Dreieck hat an den Ecken die Tiefen z_a = 2, z_b = 4 und z_c = 8. Welche Tiefe hat das Pixel mit den Gewichten 0,25 / 0,25 / 0,5?
Lösung anzeigen
z = 0,25 · 2 + 0,25 · 4 + 0,5 · 8 = 0,5 + 1 + 4 = 5,5.
